## Install in a verified checkout

- Write these exact files only after checking for existing files; compare the packet hashes. Never overwrite modified runtime/config files silently.
- Import createExperimentRouter from ./lib/infinite-experiments/runtime.mjs and manifest/deployment from config.mjs.
- Invoke the router for document navigation. Deny reserved internal artifact paths. Compose rewrite decisions with @vercel/functions rewrite() only when existing middleware permits normal routing; preserve existing auth/redirect responses.
- Private/no-store headers supplied by the router must survive every experiment-path response, including fallbacks. Internal static artifact paths must stay outside sitemap/public document lists.
- Build immutable control/test HTML artifacts at the manifest's paths, with their actual SHA-256 values and the public page's canonical URL. Relative assets resolve against the PUBLIC URL.
- Bridge the site's existing consent decision into the configured consent cookie, including revocation. On denial or revocation the helper expires __Host-infinite-person and every __Host-infinite-exp-* cookie, so no experiment identifier persists in the browser and a later grant enrols as a new person. The browser helper never initialises, resets or reconfigures an analytics provider.
- Call recordExposure() from the page after the consent decision is known. It posts one first-party exposure beacon to the configured same-origin path. Do not call any analytics provider from it. Create the helper with createExperimentClient({ siteSourceKey, getVisitorId, exposurePath, consentMode, consentCookie, getConsentDecision, consentStorageKey, personCookieName }): siteSourceKey is the pixel's public key and is required (construction throws invalid_site_source_key without it); getVisitorId returns the pixel's anonymousId when present; exposurePath (default /infinite/experiment) is the same-origin path the site forwards to Infinite's exposure endpoint. loaded() bridges consent and then records the exposure. bootstrap() is a deprecated no-op kept so a version 1 call site keeps working once it passes siteSourceKey; it configures nothing.
- Supply a random signing secret of at least 32 characters through server deployment env (INFINITE_EXPERIMENTS_SIGNING_SECRET). It signs assignments and seeds the deterministic split. Rotating it invalidates every existing assignment (those visitors fall back to original) while new visitors keep enrolling under the new secret; to stop a test, use INFINITE_EXPERIMENTS_ENABLED. No provider key belongs in this bundle.
- Leave INFINITE_EXPERIMENTS_ENABLED unset until deployed A/A routing, privacy, identity/exposure, cache isolation and rollback checks pass. This API cannot activate a test.
- INFINITE_EXPERIMENTS_ALLOW_PREVIEW is a PREVIEW-TARGET-ONLY variable and is not a second switch: set it to "1" on the preview environment alone to rehearse the deployed bytes on a preview deployment, which admits that deployment's own generated hostnames (VERCEL_BRANCH_URL, VERCEL_URL) and no others. Production must NEVER set it; with it unset the runtime serves original content on every preview deployment and the host allow-list stays exactly the production hosts. INFINITE_EXPERIMENTS_ENABLED remains the only variable that starts or stops a test, on preview and production alike, and a rehearsal still needs it set to "1" on that same preview target.

## Control and limits

The runtime decides control/test itself, with no network call: HMAC-SHA256 of the experiment id, revision and a first-party person id under the signing secret, split 50/50 (the only allocation this version accepts, frozen in the manifest). The person id is 128 random bits minted by the middleware into the readable __Host-infinite-person cookie on the first navigation; an unconsented visitor, a browser privacy signal, a bot or a prefetch receives original content and no cookie. INFINITE_EXPERIMENTS_ENABLED is the kill switch: anything but "1" returns original content to fresh and returning visitors alike, so flipping it and redeploying is the emergency stop. INFINITE_EXPERIMENTS_ALLOW_PREVIEW is its preview-target-only companion and changes no policy: it neither starts nor stops a test, it only lets a preview deployment answer for its own generated hostnames so the deployed bytes can be rehearsed before production, and production never sets it. enrollmentEndsAt and endsAt are frozen in the manifest and enforced by the deployed bytes: nobody enrols after the cutoff, existing participants keep their arm until endsAt, then everyone sees original. Appending ?__infinite_original=1 to a page URL always serves original content without assigning anyone; use it for screenshots and verification. A fallback is an availability measure, not valid evidence of an A/B win; measurement failures require reconciliation. The browser records exposure once per person per revision: recordExposure() posts a beacon whose eventId is derived from the experiment, revision and person id, so a reload or a retry names the same row, and it never carries the signed assignment. Router requests do not count as rendered exposure. Actual browser emission and ingestion must be verified separately.

The app's durable repo executor, experiment-state store and desktop controls are separate integration work. Unsupported frameworks require an explicit adapter and conformance proof.
